# brainbuzzgame.com

Official website for **BrainBuzz: Daily Challenge** (Android, `com.app.dailybrainchallenge`). It promotes the app and has all eight of the app's games playable free in the browser, with the same rules, levels and scoring as the app, plus three website-only games: 2048 Merge Challenge, Word Detective and Sudoku Daily.

It's a static site: HTML, CSS and vanilla JavaScript modules, with no framework and no runtime dependencies. A small Node script renders the pages from templates so the header, footer and SEO tags live in one place.

## Quick start

```bash
npm run build        # renders everything into dist/ (Node 12.20+, no npm install needed)
npm run serve        # http://localhost:8080, which behaves like GitHub Pages (clean URLs, 404.html)
npm test             # game engine vs the Android app's Kotlin output, plus the website-only games' rules
npm install          # only needed for the browser test below (installs puppeteer-core)
npm run test:e2e     # plays every game at every level in Chrome (server must be running)
```

`test:e2e` uses `/usr/bin/google-chrome` by default. Set `CHROME=/path/to/chrome` to use another, or `BASE=http://…` to test another server. Pass `site`, `daily`, `games` or `web` (the website-only games) to run one suite.

## How the games match the app

`assets/js/engine/` is a line-by-line port of the app's `domain/game` package: generators, difficulty rules, timings, hints and scoring. Kotlin's `kotlin.random.Random` (XorWow) is ported exactly, so seeded content is identical. **The Daily Challenge has the same 12 puzzles as the app on the same date**, using the viewer's local date just like the phone does.

`tests/fixtures/kotlin-reference.jsonl` was generated by compiling the app's real Kotlin sources with `tests/fixtures/RefMain.kt`. If you change a game in the app, regenerate it and run `npm test`:

```bash
# Uses the Kotlin compiler jars already in ~/.gradle (from building the app).
mkdir -p /tmp/kref/src && cp ../braingames/app/src/main/java/com/app/dailybrainchallenge/domain/game/*.kt \
  ../braingames/app/src/main/java/com/app/dailybrainchallenge/domain/model/GameModels.kt tests/fixtures/RefMain.kt /tmp/kref/src/
G=~/.gradle/caches/modules-2/files-2.1
CP=$(for p in org.jetbrains.kotlin/kotlin-compiler-embeddable/2.2.10 org.jetbrains.kotlin/kotlin-stdlib/2.2.10 \
  org.jetbrains.kotlin/kotlin-daemon-embeddable/2.2.10 org.jetbrains.kotlin/kotlin-script-runtime/2.2.10 \
  org.jetbrains.kotlin/kotlin-reflect/2.2.10 org.jetbrains.intellij.deps/trove4j/1.0.20200330 \
  org.jetbrains.kotlinx/kotlinx-coroutines-core-jvm/1.8.1 org.jetbrains/annotations/13.0; do
  find $G/$p -name '*.jar' ! -name '*sources*' ! -name '*javadoc*' | head -1; done | paste -sd:)

java -cp "/tmp/kref/out:$STD" RefMainKt > tests/fixtures/kotlin-reference.jsonl
```

Deliberate web differences, stated on the site:

- **Every level is free, with no rewarded videos.** In the app, Medium and Hard need a rewarded video. The website shows Google AdSense ads instead (see below), placed outside the games. Hints on the web are free, with the same count the app allows per game (its free hints plus its video hints).
- **No XP, levels, streaks, missions or achievements on the web.** Only best scores, the last difficulty and recent Daily results are kept, in `localStorage` (`bb-progress-v1`). They never sync with the app, and the site says so wherever scores appear.
- The Daily Challenge can be played once per day per browser, like in the app.

## Website-only games

`WEB_GAMES` in `assets/js/engine/models.js` lists three games that aren't in the Android app. They don't use the timed shell; each module exports `mount(stage, meta)`. Their records live under `web` in the same `bb-progress-v1` localStorage key, and every game validates what it reads, so missing or corrupt data just means starting fresh.

- **2048 Merge Challenge** (`/play/2048/`): 4×4 board, swipe (pointer events) or arrow keys/WASD. A merged tile can't merge again in the same move and a move that shifts nothing spawns nothing. The board is saved after every move; the best score is stored as `bests.MERGE.CLASSIC`, so the game card shows it.
- **Word Detective** (`/play/word-detective/`): six guesses at a five-letter word. Puzzle #1 was 1 October 2026; day N uses `ANSWERS[N mod length]` from `engine/detective-words.js`, so the word is the same everywhere on the same local date. **Never reorder or remove answers** (append only), or past and future puzzles change. Guesses are saved as they're made, so a reload can't reset the day, and stats count each day once. Sharing uses the Web Share API, then the clipboard, then a text box to copy.
- **Sudoku Daily** (`/play/sudoku/`): puzzles are generated in the browser from a seeded `KRandom` (the same per date and level). Clues are removed only while the solution stays unique; Easy and Medium must stay solvable with singles, and Hard prefers puzzles that need more. Every puzzle is verified before use, with a bundled, verified fallback set if generation ever fails.

The guess list in `detective-words.js` is the five-letter words of SCOWL (wamerican), © 2000-2011 Kevin Atkinson, used under its permissive licence (notice kept in the file). The answer list was written for BrainBuzz.

## Play Store links

All CTAs use `playUrl(placement)` in `assets/js/lib/site.js`, which adds `&referrer=utm_source=brainbuzzgame.com&utm_medium=website&utm_campaign=<placement>`. Play Console → *Statistics / Acquisition reports* then shows which placements (hero, header, results_quick-math, …) drive installs.

## Google AdSense

- **Script:** `renderPage()` in `src/layout.js` adds `adsbygoogle.js` (publisher `ca-pub-2294761279203706`) once per page through the hashed loader script, plus the `google-adsense-account` meta tag. The 404 page has no ads.
- **Manual units:** `adSlot(AD_SLOTS.home)` on the homepage (horizontalAd, between "Why BrainBuzz" and the FAQ) and `adSlot(AD_SLOTS.game)` on every game page (horizontalAd2, below the rules and tips, far from the board). `main.js` requests each unit once. Unfilled units collapse; if AdSense is blocked, `html.ads-off` hides them.
- **Auto ads, formats and consent messages** are configured in the AdSense account, not in code.
- **CSP:** Google only supports nonce-based CSP, which static hosting can't issue, so scripts are trusted by hash plus `'strict-dynamic'` (see the comment in `renderPage()`). Ads need frames, images and beacons on changing Google domains, so those directives allow `https:`.
- **`ads.txt`** in this folder is copied to `dist/ads.txt` (served at `/ads.txt`).
- **Layout check without real ads:** `node tools/build.js --ad-preview` swaps each unit for a dashed "LOCAL PREVIEW ONLY. Not an advertisement" box. It refuses to run in CI; rebuild without the flag afterwards.

## Deploy to brainbuzzgame.com (GitHub Pages)

1. The repository root is the `BrainBuzzWebsite/` folder; the workflow lives at its root in `.github/workflows/deploy.yml` (GitHub ignores workflows inside subfolders) and builds `site/`.
2. In the repo, open **Settings → Pages → Build and deployment** and set **Source: GitHub Actions** (not "Deploy from a branch", which would serve the files as-is without building). The workflow tests, builds and publishes `site/dist/` on every push to `main`.
3. In **Settings → Pages → Custom domain**, enter `brainbuzzgame.com` and save. The build also writes a `CNAME` file.
4. At your domain registrar, set these DNS records:

   | Type | Name | Value |
   | --- | --- | --- |
   | A | @ | 185.199.108.153 |
   | A | @ | 185.199.109.153 |
   | A | @ | 185.199.110.153 |
   | A | @ | 185.199.111.153 |
   | AAAA | @ | 2606:50c0:8000::153, 2606:50c0:8001::153, 2606:50c0:8002::153, 2606:50c0:8003::153 (one record each) |
   | CNAME | www | `<your-github-username>.github.io` |

   Remove any other A/AAAA/parking records for `@`. Recommended: verify the domain under your GitHub account (**Settings → Pages → Verified domains**) so nobody else can claim it.
5. Once DNS has propagated (minutes to a few hours), tick **Enforce HTTPS** in Settings → Pages.
6. Add the site to [Google Search Console](https://search.google.com/search-console) as a *Domain* property, then submit `https://brainbuzzgame.com/sitemap.xml`.
7. Optional: in Play Console, set the store listing's **Website** to `https://brainbuzzgame.com`.

**Other hosts.** Netlify and Cloudflare Pages also work with build command `node tools/build.js` and output directory `dist`. Both serve `404.html` automatically.

## Updating content

- **Screenshots:** `assets/img/screens/store-1…6.webp` are the current Play Store screenshots (540 px wide). Replace them with the same names when the listing changes.
- **Email / Play URL / app privacy policy URL:** `assets/js/lib/site.js`.
- **Privacy policy:** `privacyPage()` in `src/pages.js`. Update the "Last updated" date when you change it.
